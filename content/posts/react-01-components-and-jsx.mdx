React를 한 번도 써 본 적 없는 사람을 위한 글입니다. 설치나 프로젝트 세팅은 다루지 않고, React 코드가 왜 이렇게 생겼는지를 이해하는 데 집중합니다. HTML 태그를 쓸 줄 알고, JavaScript에서 변수·함수·객체 정도는 본 적 있다면 충분히 따라올 수 있습니다.

## 웹 페이지는 어떻게 화면이 되나

브라우저는 서버에서 받은 HTML을 읽어 화면을 그립니다. HTML은 “여기에 제목, 여기에 버튼” 같은 구조를 적어 둔 문서이고, CSS는 색·간격·레이아웃을, JavaScript는 버튼 클릭·입력·서버 요청 같은 동작을 담당합니다.

JavaScript로 `<button>`을 만들고, 클릭할 때마다 글자를 바꾸고, 목록에 항목을 추가하는 일을 직접 하려면 대략 이런 흐름이 필요합니다.

1. DOM(문서 객체 모델)에서 요소를 찾는다
2. 이벤트를 연결한다
3. 데이터가 바뀔 때마다 어느 노드를 어떻게 고칠지 일일이 코드로 쓴다

글 하나, 장바구니 하나만 해도 “데이터 → 화면” 연결 코드가 빠르게 길어집니다. 어디를 고쳐야 하는지 놓치기 쉽고, 같은 UI를 여러 페이지에서 쓰려면 복사·붙여넣기가 늘어납니다.

React는 이 문제를 UI를 작은 조각(컴포넌트)으로 나누고, 데이터가 바뀌면 그에 맞는 화면을 다시 그리게 하는 방식으로 풉니다. DOM에서 버튼을 찾아 `textContent`를 바꾸는 식이 아니라, “지금 `count`가 3이면 화면에 3을 보여 준다”고 적는 쪽에 가깝게 생각하게 만드는 도구입니다.

## React가 말하는 두 가지 약속

React 코드를 읽을 때 자주 보는 말은 두 가지입니다.

**1. UI는 데이터(state)의 함수다**

화면에 보이는 것은 “지금 값이 무엇인가”에서 결정됩니다. 숫자가 0이면 0을, 1이면 1을 보여 줍니다. 값이 바뀌면 React가 그 부분을 다시 그립니다(리렌더).

**2. UI는 컴포넌트 트리다**

페이지 전체가 하나의 거대한 함수가 아니라, `Header`, `PostList`, `Button`처럼 이름 붙은 조각이 겹겹이 쌓인 구조입니다. 같은 `Button`을 여러 번 재사용할 수 있습니다.

아직 `useState` 같은 API는 여기서 다루지 않습니다. “조각으로 나눈다”와 “값에 따라 화면이 정해진다”만 기억하면 됩니다.

## 컴포넌트란

컴포넌트는 화면의 한 덩어리를 이름 붙여 둔 것입니다. React에서는 보통 함수 하나가 컴포넌트 하나입니다. 함수 이름은 대문자로 시작하는 것이 관례입니다 (`Button`, `UserCard`).

```jsx
function Greeting() {
  return <h1>안녕하세요</h1>;
}
```

`Greeting`은 “인사 제목을 보여 주는 조각”입니다. 다른 파일에서 `<Greeting />`처럼 태그처럼 불러 쓸 수 있습니다.

컴포넌트를 나누는 정해진 공식은 없습니다. 보통 이렇게 생각합니다.

- 한 번에 이해하기 어렵다 → 더 작게 쪼갠다
- 두 곳 이상에서 쓴다 → 컴포넌트로 뺀다
- 역할이 다르다 (목록 vs 항목, 폼 vs 입력칸) → 분리한다

처음에는 조금 크게 써도 괜찮습니다. 읽다가 “이 부분만 따로 테스트하고 싶다” 싶을 때 쪼개면 됩니다.

## JSX — JavaScript 안의 UI 문법

`return` 뒤에 보이는 `<h1>...</h1>` 같은 문법이 JSX입니다. HTML과 비슷해 보이지만 JavaScript의 확장 문법이고, 브라우저가 바로 이해하지 못합니다. 빌드 도구(예: Next.js, Vite)가 일반 JavaScript로 바꿔 줍니다.

아래는 JSX를 쓸 때 자주 걸리는 규칙만 정리합니다.

### 1. 반드시 하나의 최상위 요소

```jsx
// ❌ 형제 요소 두 개를 바로 return 할 수 없음
function Bad() {
  return (
    <h1>제목</h1>
    <p>본문</p>
  );
}

// ✅ Fragment로 감싸기 (<></> 또는 <Fragment>)
function Good() {
  return (
    <>
      <h1>제목</h1>
      <p>본문</p>
    </>
  );
}
```

### 2. HTML과 다른 속성 이름

| HTML | JSX |
|------|-----|
| `class` | `className` |
| `for` | `htmlFor` |
| `onclick` | `onClick` (camelCase) |

React는 DOM 속성 이름을 JavaScript 쪽 관례에 맞춥니다. `class`를 쓰면 경고가 나거나 동작하지 않습니다.

### 3. 중괄호 `{}` — JavaScript 끼워 넣기

태그 안에서 JavaScript 값·표현식을 쓰려면 `{}`로 감쌉니다.

```jsx
const name = "진";
const count = 3;

function Profile() {
  return (
    <p>
      {name}님, 메시지 {count}개
    </p>
  );
}
```

문자열 속성도 가능합니다.

```jsx
<img src={avatarUrl} alt={`${name} 프로필`} />
```

### 4. JSX도 값이다

JSX는 함수 호출의 결과처럼 다룰 수 있습니다.

```jsx
const element = <strong>강조</strong>;

function Note() {
  return <div>{element}</div>;
}
```

그래서 `if`, `map`, 변수에 담기 등 일반 JavaScript와 자연스럽게 섞입니다.

### 5. `true` / `false` / `null` / `undefined`는 화면에 안 그림

조건부로 아무것도 안 보이게 할 때 유용합니다.

```jsx
{isLoggedIn ? <Dashboard /> : <LoginForm />}
{error && <p role="alert">{error}</p>}
```

## props — 부모가 자식에게 넘기는 값

같은 `Avatar` 컴포넌트라도 사람마다 사진 URL이 다릅니다. 그 차이를 props(properties)로 넘깁니다. props는 읽기 전용입니다. 자식이 props를 직접 수정하면 안 됩니다.

```jsx
function Avatar({ name, src }) {
  return (
    <figure>
      <img src={src} alt={`${name} 프로필`} />
      <figcaption>{name}</figcaption>
    </figure>
  );
}

function Page() {
  return (
    <Avatar name="진" src="/jin.png" />
  );
}
```

`<Avatar name="진" src="/jin.png" />`는 “`Avatar` 함수를 `name`, `src`와 함께 호출하라”와 같습니다.

props를 구조 분해할 때 기본값을 줄 수 있습니다.

```jsx
function Badge({ label = "NEW" }) {
  return <span>{label}</span>;
}
```

### props를 객체 하나로 받기

항목이 많을 때는 객체로 묶어 넘기기도 합니다.

```jsx
function UserCard({ user }) {
  return <p>{user.name}</p>;
}

<UserCard user={{ name: "진", age: 20 }} />
```

나중에 TypeScript를 쓰면 이 형태를 타입으로 묶기 좋습니다.

## children — 태그 사이에 넣는 내용

`<Card>...</Card>` 사이에 넣은 내용은 `children` prop으로 들어옵니다.

```jsx
function Card({ title, children }) {
  return (
    <section>
      <h2>{title}</h2>
      <div>{children}</div>
    </section>
  );
}

function App() {
  return (
    <Card title="공지">
      <p>오늘 배포 예정입니다.</p>
    </Card>
  );
}
```

`children`은 문자열 하나일 수도, 여러 JSX 요소일 수도, `null`일 수도 있습니다. 레이아웃(틀)은 부모 컴포넌트가, 안쪽 내용은 사용하는 쪽이 정하는 패턴에 자주 쓰입니다.

## 컴포넌트 파일을 읽는 순서

낯선 React 파일을 열었을 때 추천 순서입니다.

1. `export default` 또는 export된 함수 이름 — 무엇을 그리는 컴포넌트인가
2. props — 밖에서 무엇을 받는가
3. `return` JSX — 실제로 무엇이 화면에 나오는가
4. hooks (`useState`, `useEffect` 등) — 별도 주제

한 번에 위에서 아래로만 읽지 않아도 됩니다. `return`부터 보고 화면 모양을 잡은 뒤 props와 state를 거슬러 올라가도 괜찮습니다.

## 정리

- 웹 UI는 HTML 구조 + CSS + JS 동작으로 만들어지고, JS만으로 DOM을 직접 고치면 복잡해지기 쉽습니다.
- React는 UI를 컴포넌트로 나누고, 데이터에 맞는 화면을 다시 그리게 돕습니다.
- JSX는 JavaScript 안에서 UI를 적는 문법입니다. className, 중괄호, 하나의 최상위 요소 규칙을 지킵니다.
- props는 부모 → 자식 입력, children은 태그 사이 내용입니다. 둘 다 읽기 전용으로 다룹니다.
